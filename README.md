## Подключить машину

Нужен Python 3.11+. Скачать [codex_usage.py](https://176.124.205.198.sslip.io/codex_usage.py)
с сайта (обычный вход по паролю) или из [приватного репозитория](https://github.com/Nikkfh5/codex-usage) и выполнить:

```sh
python codex_usage.py install
python codex_usage.py doctor
```

На macOS/Linux команда обычно называется `python3`. Если в локальном
`~/.codex/config.toml` уже настроен OTLP этого сайта, адрес, ключ и имя машины
подхватываются автоматически. Иначе:

```sh
python codex_usage.py install --machine MY-MACHINE --endpoint https://176.124.205.198.sslip.io/v1/usage
```

Установщик попросит **ключ приёма** скрытым вводом; в аргументы команды его не писать.
Для автоматической установки поддерживаются `CODEX_USAGE_TOKEN`, `CODEX_USAGE_MACHINE`
и `CODEX_USAGE_ENDPOINT`. Не используйте одно имя для разных физических машин.

Установка копирует утилиту и приватную конфигурацию в `~/.codex/usage-sender` и включает
автозапуск: скрытая задача Windows, launchd на macOS, пользовательский systemd на Linux.
Linux-служба работает пока доступен пользовательский manager; для постоянной работы
без входа нужен настроенный администратором lingering. `--no-autostart` сохраняет только
настройки; затем можно запустить `python codex_usage.py run` вручную.
Другой `CODEX_HOME`/`--codex-home` подключать с отдельным `--state-dir`.

**По умолчанию учитываются новые сессии, созданные после установки.** Старые и
скопированные журналы не получают автоматически имя новой машины. После проверки
происхождения существующую сессию можно подключить повторной установкой:

```sh
python codex_usage.py install --adopt-session THREAD-ID
```

Флаг повторяемый. Использовать `session_meta.id` / `thread_id`, а не API `session_id`:
у подагентов они различаются. Сервер блокирует переход сессии, уже встречавшейся
под другой машиной или у другого отправителя. Активные процессы Codex закрывать не нужно.
При обновлении повторить `install`: ID отправителя, граница и история сохраняются.

## Как устроена доставка

`JSONL Codex → локальный ledger.sqlite → HTTPS → SQLite Aeza → сайт`.

- Завершённая JSONL-строка и курсор фиксируются одной транзакцией. Неполная строка ждёт
  следующего обхода; используются только `token_usage_record`, не накопительные суммы.
- Пакеты до 200 ответов. Сервер подтверждает конкретные `response_id` после commit.
  Потеря ACK, HTTP 401/429/5xx и обрыв сети не удаляют очередь. Повтор того же ID
  идемпотентен; изменившийся payload или другая машина дают конфликт.
- Подтверждённые записи остаются локально. Сверка дневных SHA-256 обнаруживает потерю
  серверной истории и повторяет доставку, в том числе после восстановления старой базы.
- Прямой HTTPS не использует переменные старого прокси Codex. При необходимости
  задаётся `--proxy http://127.0.0.1:PORT`; TLS проверяется, перенаправления запрещены.
- После полного чтения и ACK сервер переключает **целую сессию** на журнал. Её старые
  OTLP-записи сохраняются для аудита, но не суммируются с журналом. До переключения
  учитывается OTLP. Исторические суммы могут измениться: состав двух источников различается.
- Очередь хранит только идентификаторы, время, модель/режимы и счётчики. Prompt,
  tool output и email туда не копируются. Настройки с ключом хранить приватно.

Граница гарантии: Codex должен записать ответ в доступный локальный журнал, а локальный
диск должен сохраниться. Формат `token_usage_record` проверен на CLI 0.153.4.
Неподдерживаемый формат отмечается ошибкой. Облачные задачи и неизвестные клиентские
версии не считаются автоматически покрытыми. Готовый установщик не означает, что
он уже установлен на всех машинах.

## Проверить или восстановить

```sh
python codex_usage.py status
python codex_usage.py doctor
python codex_usage.py once
```

`status` показывает сохранённый размер очереди и последнюю ошибку; `doctor` добавляет
проверку SQLite и локальных настроек. `once` выполняет чтение и сетевую сверку.
В карточке машины — возраст последнего отчёта, очередь на тот момент, число
переключённых сессий и ошибка. При отключённой машине это старый отчёт, не текущая очередь.
У машин без отправителя явно указано, что полнота OTLP не проверяется.

При `HTTP_401` проверить ключ приёма; при `network_error` — маршрут к сайту и явный прокси;
при `HTTP_409` — происхождение ID/сессии. `unsupported_format`/ошибки JSONL требуют
проверки версии и конкретного файла, а не пропуска строки. Не удалять `ledger.sqlite`
или `config.json` для сброса ошибки: там история и стабильная идентичность отправителя.
Системные ошибки диска/конфигурации сохраняются в `runtime-error.txt` без секретов.

Проверка сервера:

```powershell
ssh aeza 'systemctl is-active codex-usage nginx codex-cert-renew.timer'
ssh aeza 'curl -fsS http://127.0.0.1:8768/health'
ssh aeza 'curl -fsS http://127.0.0.1:8768/api/v1/machines'
```

HTTP 200 и нулевая очередь сами по себе не доказывают полноту. Для фиксированного
периода сверить ID, дневные digest и счётчики локального ledger с сервером и CSV.
Пустые корзины не заменяются нулевым расходом.

## Проверки и выпуск

```sh
python -m unittest -v test_server test_analytics test_pricing test_sync test_codex_usage
```

Полная команда — на Python 3.11+. Сервер Python 3.10+ проверяется без `test_codex_usage`;
клиент требует 3.11+. На Windows для часовых поясов нужна IANA-база `tzdata`.
Тесты проверяют потерю ACK, повторы, ошибки HTTP/диска, перезапуск, откат базы,
неполные/переписанные файлы, конфликты машин и отсутствие приватных текстов.

Выпуск: SQLite backup через `sqlite3.Connection.backup`, новый каталог
`/opt/codex-usage/releases/<release>`, тесты на Linux и SHA-256, затем атомарная смена
`current` и restart сервиса. Nginx должен пропускать `/v1/logs` и `/v1/usage`
с Bearer без Basic; остальной сайт защищён Basic. Перед reload выполнить `nginx -t`.
Не менять файлы выпущенной версии на месте. При откате сохранить новую базу;
возврат старого кода также возвращает OTLP-учёт и перестаёт принимать журнал.
