## Если расход снова кажется заниженным

1. Зафиксировать машину и `[start,end)` в UTC. `period=720` на сайте — 30 дней,
   а остаток подписки относится к другому окну; проверить также активные фильтры.
2. Проверить сервис, `/health` и `/api/v1/machines`. Свежая карточка подтверждает
   получение сигнала, но не доставку каждого ответа.
3. На Windows проверить `netsh interface portproxy show all`, фактические слушающие
   порты и ошибки `opentelemetry_sdk` в `%USERPROFILE%\.codex\logs_2.sqlite`.
   Закрытый порт назначения делает перенаправление бесполезным. Проверять маршрут
   каждого ещё работающего процесса: старый процесс может сохранить прежний прокси.
4. Сопоставить уникальные `response_id` из `token_usage_record` с сервером.
   Старый OTLP не содержит `response_id`: дополнительно сопоставлять сессию, модель,
   время и счётчики, проверяя другие машины. Найдены одинаковые счётчики с разницей
   временных меток до 31 минуты; такие случаи не считать автоматически пропусками.
5. Для восстановления использовать только доказанные пропуски: свежий SQLite backup,
   dry-run, транзакция, повторная сверка без новых вставок, `quick_check`, API и CSV.
   Предыдущий инструмент: `/root/codex-usage-recovery-20260914/recover.py`.
   Он рассчитан на подготовленный JSON, не сканирует журналы сам; окно совпадения
   15 секунд не доказывает отсутствие задержанного ответа. Не запускать вслепую.

Нужное исправление: обеспечить рабочий маршрут экспортёра и восстановить
подтверждённые пропуски. Для гарантии полноты нужна повторяемая сверка локальных
журналов каждой машины: один успешный POST не исправляет прошлые потери.

## Почему токены не равны проценту подписки

Сайт показывает наблюдаемые токены и отдельно их **эквивалент по тарифам API**.
Он не получает фактическое списание лимита подписки. По
[официальной документации OpenAI](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan),
расход зависит от модели, контекста, reasoning, инструментов и кэширования;
локальные и облачные задачи делят лимит, могут действовать недельные ограничения.
Поэтому постоянного коэффициента «миллион токенов = X% подписки» здесь нет.
Одинаковые токеновые суммы на разных моделях не обязаны одинаково расходовать лимит.
Даже полностью доставленная телеметрия этих машин не доказывает покрытие всей
активности подписки. Процент остатка — повод проверить доставку, но не эталон
для корректировки токеновых сумм.

## Формулы и границы данных

Учитываются `codex.sse_event` с `event.kind=response.completed`.
`total = input + output`; кэш входит в input, reasoning входит в output.
Четыре части — вход без кэша, кэш, выход без reasoning и reasoning — складываются в total.

| Показатель | Формула |
| --- | --- |
| Кэш / все | 100 × cached / (input + output) |
| Кэш / вход | 100 × cached / input |
| Reasoning / все | 100 × reasoning / (input + output) |
| Reasoning / выход | 100 × reasoning / output |
| Вход без кэша / все | 100 × (input − cached) / (input + output) |
| Среднее на событие | total / количество response.completed |

Доли считаются от сумм, не усреднением процентов запросов. При нулевом знаменателе
или неизвестном компоненте результат null (на экране «—»). Если у одного события
неизвестен дополнительный счётчик, соответствующая полная сумма также null.
Пустая выборка не выдаётся за доказанный нулевой расход.

Effort берётся из `model_reasoning_effort` или `reasoning_effort` самого события ответа.
`service_tier=priority/fast` отображается как Fast; `default/standard` — как стандартный.
Остальные явно переданные значения сохраняются отдельно. Отсутствующие режимы —
«неизвестно»: текущая конфигурация или начало сессии не подставляются в старые ответы.
Старый приёмник эти поля не сохранял, поэтому исторические режимы восстановить нельзя.
Проверка Codex CLI 0.153.4 подтвердила реальные `effort=low`, `service_tier=priority`;
у отдельного события прогрева режимы отсутствовали и остались неизвестными.

Запросы без выходных токенов учитываются по умолчанию; их можно исключить фильтром.
В экспорте встречается прогрев, но его влияние на оплату не установлено.
Это наблюдаемые токены, не счёт за подписку или оценка качества. Сравнение разных
задач и контекстов не доказывает причинный эффект изменения модели или effort.

Карточка машины обновляется при любом идентифицированном событии `codex.*`.
«Телеметрия» означает получение сигнала в последние две минуты; отсутствие сигнала
не доказывает выключение машины. Отдельных heartbeat-служб на клиентах нет.
У старых записей время получения неизвестно, показывается время последнего события.

Полнота App, IDE, подагентов, компактизации и внутренних запросов не доказана.
История до подключения не импортируется. При недоступном сервере возможны пропуски:
долговечная очередь клиента не подтверждена. Пустые корзины не дорисовываются нулями.
Сравнение с периодом до первых наблюдений явно помечается неполным.

В наблюдаемом экспорте нет response_id. Отпечаток машины, сессии, времени, модели и
счётчиков устраняет повторную доставку идентичного события. Это не строгая гарантия
уникальности разных ответов при совпадении всех этих полей. Новые метаданные режимов
не меняют прежний отпечаток и не удваивают повторно доставленные события.

Приёмник сохраняет разрешённые метаданные и счётчики; prompt, tool output, email и
account_id отбрасываются. Сырые пакеты на диск не пишутся. Экспортёр может передавать
дополнительные поля даже при `log_user_prompt=false`; адрес назначения должен быть доверенным.

## Интерфейс для агентов

Стоимость оценивается по опубликованным тарифам на 2026-09-06 из `pricing.py`:
[OpenAI API pricing](https://developers.openai.com/api/docs/pricing) и
[расчёт кэша](https://developers.openai.com/api/docs/guides/prompt-caching).
Учтены шесть наблюдаемых моделей, Fast/Flex, отдельная запись кэша новых моделей
и длинный контекст. GPT-5.5 использует длинный тариф для сохранённой сессии, если в ней
наблюдалось превышение 272000 входных токенов. Неизвестная скорость и Auto считаются
по Standard с явной пометкой, без изменения фактического режима. Неполные счётчики
и неопубликованные тарифы остаются без оценки; показаны сумма известной части и покрытие.
Тарифы фиксированы в выпуске, не загружаются с внешнего сайта при каждом обновлении страницы.
Это пересчёт токенов по текущей таблице, не исторический счёт и не списание подписки.
Комиссии инструментов, региональные надбавки, налоги и договорные скидки не включены.

[agent-guide.md](agent-guide.md) описывает контракт, формулы и порядок анализа.
Все GET доступны с тем же Basic auth, что и сайт; ключ приёма для чтения не подходит.

- `/api/v1/schema` — версия, параметры и семантика.
- `/api/v1/analytics` — суммы, сравнение, графики, группировки и сессии.
- `/api/v1/events` — события с пагинацией, `limit=1..1000`, `cursor`.
- `/api/v1/export.csv` — все события выбранного интервала.
- `/api/v1/machines` — сохранённый список машин и свежесть телеметрии.

POST `/api/v1/machines/visibility` принимает JSON `{machine, hidden}` и требует
`X-Codex-Usage-Action: visibility`. Он защищён Basic auth сайта и проверкой запросов
из браузера; изменяет только общую видимость карточки. В SQLite добавляется таблица
`machine_preferences`; её настройки переживают перезапуск и поступление новых событий.

Период: `hours=1..744` (по умолчанию 720) либо Unix ms `start` и `end`, интервал
`[start,end)`. Фильтры: `machine`, `model`, `effort`, `tier`, `session`,
`zero_output=include|exclude`, `timezone=Europe/Moscow`. Опечатки параметров отклоняются.
Для пагинации и сравнения выгрузок фиксируйте время и фильтры. API не блокирует
параллельную доставку новых событий: сохраняйте выгрузку для повторного анализа.
Старый `/api/usage?hours=...` сохранён для совместимости (до 744 часов).

задаёт уникальное постоянное имя машины и проверяет фактическую отправку.
Вход в аккаунт Codex сам по себе не подключает хост к графику.

Рекомендуемый endpoint: `https://176.124.205.198.sslip.io/v1/logs`.
Имя использует wildcard DNS sslip.io; на ml04 DNS64/NAT64 обеспечивает доступ при
отсутствии прямого IPv4. Проверено настоящим запросом Codex и сверкой его счётчиков.
Новый процесс CLI читает конфигурацию; уже открытые App/IDE/CLI могут требовать перезапуска.
При отдельном CODEX_HOME нужен тот же блок конфигурации с тем же именем хоста.

## Сервер и выпуск

- SSH: `ssh aeza`; приложение — `/opt/codex-usage/current`, ссылка на проверенный выпуск.
- SQLite: `/var/lib/codex-usage/usage.sqlite`, пользователь `codex-usage`.
- Python 3.10+ со стандартными sqlite3 и zoneinfo; сторонних библиотек нет.
- Только `127.0.0.1:8768`; `/etc/systemd/system/codex-usage.service`, лимит 256 МБ.
- Nginx: `/etc/nginx/sites-available/codex-usage`; публичный HTTPS с Basic auth.
- POST `/v1/logs` использует отдельный Bearer token.
- Секреты: `/etc/codex-usage/dashboard.htpasswd`, `/etc/codex-usage/ingest.token`.

Проверка: `systemctl status codex-usage.service nginx.service codex-cert-renew.timer`.
Журнал: `journalctl -u codex-usage.service -n 50`. Перезапуск: `systemctl restart codex-usage.service`.
Выпуск переносится в новый каталог, сверяется по SHA-256, тестируется на сервере,
затем ссылка current переключается атомарно. База используется на месте.
Миграция v2 добавляет индекс времени и таблицу активности; старые события не переписывает.
Для отката можно вернуть предыдущую ссылку и перезапустить только этот сервис.

Let's Encrypt обслуживает отдельные сертификаты IP и DNS. Certbot установлен в
`/opt/codex-usage/certbot-venv`, конфигурация — `/etc/codex-usage/acme`.
`codex-cert-renew.timer` проверяет продление дважды в сутки с задержкой до 30 минут;
deploy hook проверяет Nginx и выполняет reload. Прежние dry-run обоих сертификатов прошли.
Старый VPN удалён по разрешению владельца; квитанция — `/opt/codex-usage/vpn-retirement.json`.
