# Codex Usage: интерфейс для анализа

Базовый адрес: https://176.124.205.198.sslip.io

Все аналитические методы — GET, только чтение. Они защищены HTTPS Basic auth:
используйте логин и пароль сайта, полученные от владельца. Ключ отправки OTLP
не даёт права читать аналитику. Не печатайте credentials и не помещайте их в Git.

## Начало

- `GET /api/v1/schema` — версия, параметры и точные определения показателей.
- `GET /api/v1/machines` — известные машины и время получения последней телеметрии.
- `GET /api/v1/analytics?hours=720&timezone=Europe%2FMoscow` — последние 30 дней.

Фильтры: `machine`, `model`, `effort`, `tier`, `session` (точное совпадение).
`tier=fast` объединяет явно переданные `fast` и `priority`, `tier=standard` —
явные `default` и `standard`. Отсутствующее поле — `unknown`; `auto` и `flex`
сохраняются отдельно. Режимы берутся с каждого события ответа, а не из текущего config.toml.
Старые события, для которых режим ранее не сохранялся, остаются неизвестными.

`zero_output=include` (по умолчанию) или `exclude` управляет включением событий
без выходных токенов во все суммы и сравнения. Нулевой выход не доказывает прогрев
или бесплатность запроса.

Вместо `hours` можно задать `start` и `end` в Unix milliseconds. Интервал
полуоткрытый: `[start,end)`, не длиннее 31 дня. `timezone` — IANA-имя для дневных
столбцов, по умолчанию UTC. Дневные границы учитывают переходы летнего времени.
Сравнение — предыдущий соседний интервал той же длительности и с теми же фильтрами.

## Состав ответа

`totals`: суммы и доли; `comparison`: предыдущие суммы и относительные изменения;
`timeline`, `previous_timeline`: наблюдаемые временные корзины;
`breakdowns`: машина, модель, effort, tier; `sessions`: 100 сессий с наибольшим объёмом;
`recent_events`: последние 20 событий; `machine_activity`: свежесть телеметрии;
`coverage`: доступность режимов и начало наблюдений. Все суммы относятся к одним фильтрам.

Для полной выборки используйте `GET /api/v1/events?start=...&end=...&limit=1000`.
Зафиксируйте start/end из первого аналитического ответа и все фильтры. Повторяйте
запрос с `cursor=<next_cursor>`, пока next_cursor не станет null. Порядок —
(timestamp_ms,id). Это не снимок базы: при параллельной поздней доставке возможны новые
события; для воспроизводимого анализа сохраните выгрузку и её generated_at_ms.
`GET /api/v1/export.csv` принимает те же фильтры и выгружает весь выбранный интервал.
Пустое значение CSV означает неизвестное, не ноль.

## Оценка стоимости API

`pricing` содержит дату и источники используемого тарифа; в `/api/v1/schema` также
есть `pricing.rates_per_million`. Стоимость переоценивает выбранные токены по этой
таблице, включая старые события. Это эквивалент API, не исторический счёт или подписка.

- Формула: `((input − cached − cache_write) × input_rate + cached × cache_rate +
  cache_write × write_rate + output × output_rate) / 1e6`. Reasoning входит в output.
- У GPT-5.6/6 запись кэша имеет свой тариф. `uncached_input_tokens` в токеновой аналитике
  включает запись кэша; не умножайте весь этот показатель на обычный входной тариф.
- Известные Fast/Flex учитываются. Unknown/Auto используют Standard **только как допущение
  цены**, с `api_price_assumed_tier=true`; исходное поле tier не меняется.
- Длинный контекст учитывается по правилам модели. Для GPT-5.5 учитывается превышение
  272000 входных токенов в любом сохранённом событии этой машины/сессии, включая события
  вне выбранного периода. История до начала сбора неизвестна.
- `api_cost_usd`: полная оценка, null при любом неоценённом событии.
- `api_cost_known_usd`: сумма оценённых событий; `api_cost_breakdown_known_usd`: её части.
- `api_priced_events`, `api_unpriced_events`, `api_price_coverage_pct`,
  `api_assumed_tier_events`, `api_unpriced_reasons`: покрытие и допущения.
- У событий есть `api_price_tier`, `api_price_context`, `api_price_reason` и части стоимости.
  Неизвестная модель, неподдерживаемый тариф или недостающий счётчик не заменяются нулём.
- Комиссии инструментов, региональные надбавки, налоги и индивидуальные скидки не включены.

В графиках и рейтинге стоимости `api_cost_known_usd` относится только к оценённым событиям.
Не сравнивайте частичные суммы как полные, особенно при разном покрытии.

`machine_activity[].hidden` — только видимость карточки. История, фильтры, сбор и суммы
сохраняются. POST `/api/v1/machines/visibility` меняет эту обратимую настройку для всех
просмотров сайта; для обычного анализа агенту достаточно методов GET.

## Как читать числа

- total = input + output. Это наблюдаемые токены, не списание подписки.
- source=journal: подтверждённые ответы активированной сессии; иначе OTLP. Исходные OTLP-строки сохранены, но после перехода не суммируются с журналом. response_id доступен у журнала.
- Идентичность сессии — session_meta.id/thread_id; API session_id подагента может указывать на родителя.
- cached — часть input; reasoning — часть output. Не прибавляйте их к total повторно.
- uncached_input = input − cached; visible_output = output − reasoning.
- cache_total_pct = cached / total × 100; cache_input_pct = cached / input × 100.
- reasoning_total_pct = reasoning / total × 100; reasoning_output_pct = reasoning / output × 100.
- Проценты вычислены от сумм, не как среднее процентов отдельных запросов.
- Если знаменатель нулевой или компонент неизвестен, процент null.
- Один неизвестный компонент делает соответствующую полную сумму null: частичная известная
  сумма не выдаётся за полный результат. Пустая выборка не доказывает нулевой расход машины.
- average_tokens = total / количество событий завершения ответа. Это не средняя цена задачи.
- Отсутствие свежих событий не доказывает отключение хоста. Поле journal содержит последний отчёт фонового отправителя; его очередь может быть устаревшей.
- completeness = unknown: отсутствие зарегистрированных ошибок не доказывает отсутствие потерь.

## Предлагаемый порядок анализа

1. Назовите период, фильтры, дату первых наблюдений и известность режимов.
2. Найдите машины и сессии, объясняющие основной объём. Разделите общий input и input без кэша.
3. Сравните модели/effort/tier внутри сопоставимых задач; общие рейтинги разных задач описательные.
4. Для каждого предложения оптимизации приведите исходные числа и небольшой проверяемый эксперимент.
5. Для денег используйте оценку API вместе с её тарифом, покрытием и допущениями.
   Качество работы и причинный эффект смены режима требуют дополнительных данных.

Пример чтения с уже настроенными переменными окружения:

```sh
curl --fail --silent --show-error \
  --user "$CODEX_USAGE_USER:$CODEX_USAGE_PASSWORD" \
  'https://176.124.205.198.sslip.io/api/v1/analytics?hours=720'
```

На сайте кнопка «Данные для агента» скачивает текущую аналитическую выборку и промпт.
Переписка, prompt, результаты инструментов и учётные данные в выгрузку не входят.
